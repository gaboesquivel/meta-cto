# Prove the verdict before slice 3: human-confirmed ground truth and preset bars

Status: Proposed (2026-10-29). Adds to `PRODUCT.md` (MVP slices, main metric and kill criterion, riskiest assumptions) and `GLOSSARY.md` (Workspace, new terms); leaves the 85% same-need precision kill line and decision 0002's metric definitions unchanged.

**Context.** Slices 1 and the review queue ([spec 001](../specs/001-check-before-create.md), [spec 002](../specs/002-review-queue.md)) are live, but nothing shows the verdict works. Production metrics are empty (the backlog scan was never run there), they cannot tell pilot use from demo, seed or eval activity, and the Held-Out Set has 25 pairs (10 same-need positives, 4 of 25 on one target) that an agent both wrote and labeled. Slice 3 summarizes and groups whatever the verdict produces, so building it first would make unproven verdicts look authoritative. Signal has no real customers to pilot with; its users are agents filing over MCP and one or two people acting as Product Managers.

**Choice.**

1. **Prove first.** Slice 3 starts only after a proof run passes bars set before the run.
2. **Ground truth is human-confirmed.** A person confirms every label in a new Held-Out Set (v2) and in the pilot's Answer Key. Feedback is generated by a different model family than the judge. The v1 Held-Out Set stays frozen as the first reading.
3. **Held-Out Set v2:** at least 60 same-need positives, spread across targets, written without sight of the current prompt and frozen before its first run. Each prompt version runs it once; every run is logged, including failures. Readings report a 95% interval beside the point estimate.
4. **Preset bars.** Pilot Intake Duplicate Rate at most half the backlog baseline, with Review Coverage at least 80% over about 200 filings; the baseline backlog and its expected rate are fixed before the pilot. Related-need precision at least 75% on v2 keeps the three-way verdict; below it, submitters get a two-way verdict and Related becomes a human-only decision, recorded then as a direction change.
5. **Agent evidence is correctness, not acceptance.** An agent's Support or create is scored against the Answer Key; a wrong Support counts as harm. Suggestion Acceptance is reported, not evidence.
6. **Origin is recorded at the source.** Every Check and event carries where it came from (pilot, demo, seed, eval), and metrics read one origin at a time.

**Alternatives considered.**

- Agent-written labels as they are: rejected; generator, labeler and judge from one model family grade themselves, and the result convinces nobody.
- Two other model families label, a person resolves disagreements: rejected; shared model blind spots stay invisible, for a saving of a few hours.
- Suggestion Acceptance as agent evidence: rejected; agents follow the verdict by construction, so acceptance measures obedience.
- Deciding the bar after the run, or "any clear drop": rejected; invites moving the goalposts.
- Dropping Related Need now, or keeping it regardless: rejected; the first gives up a stated differentiator without evidence, the second defers the decision indefinitely.
- Growing v1 in place: rejected; prompts were tuned after v1 froze, so new pairs would mix tuned and untuned readings.

**Consequences.**

- `PRODUCT.md` gains a proof slice before slice 3, the proof bars, agent correctness as a supporting metric, the related-need threshold and two hypotheses; `GLOSSARY.md` gains Pilot Workspace, Answer Key, Origin and Held-Out Set v2, and Workspace no longer says there is one.
- Two or three hours of human labeling become a dependency of every proof reading.
- A failed bar stops slice 3; a same-need reading below 85% triggers the existing kill criterion.
